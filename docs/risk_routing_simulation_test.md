# Risk Routing Simulation Test Guide (OOD, Disagreement, Difficulty)

## 1. 개요
본 문서는 TRUST-Triage 파이프라인에서 라우터 엔진(Joint Risk Router)이 처리하는 **주요 위험 신호들에 대한 시스템 반응을 통합적으로 테스트하는 시뮬레이션 방법론**을 설명합니다.

우리 시스템은 모델의 한계를 극복하기 위해 단순히 확률값(Calibrated Probability)에만 의존하지 않고, 다음 4가지 강력한 위험 신호를 통해 위험 샘플을 `HIGH_RISK_UNCERTAIN` 큐로 라우팅하여 심층 분석(CAPA, Speakeasy 등)을 받도록 설계되어 있습니다.

## 2. 테스트 대상 위험 신호 (Risk Signals)
새로운 외부 데이터셋을 수집하는 대신, 기존 평가 데이터셋(`X_eval`, 48만 건) 내에서 각 위험 신호 점수를 추출하여 가상의 테스트셋으로 활용합니다.

### 2.1. OOD (Out-of-Distribution) 점수
* **지표**: Isolation Forest 알고리즘의 `decision_function` 점수 (`ood_score < 0.0`)
* **근거**: 정상적인 학습 데이터 분포를 스스로 학습한 뒤, 새로운 데이터가 기존 분포에서 얼마나 이질적인지 직접적으로 점수화합니다. 낯선 패턴(신종 악성코드 등)에 의한 오탐을 방지합니다.

### 2.2. 모델 불일치도 (Model Disagreement)
* **지표**: XGBoost와 LightGBM 두 모델 간의 예측 확률 차이 (`|p_xgb - p_lgb| >= 0.3`)
* **근거**: 앙상블 모델 간의 의견 불일치도는 인식론적 불확실성(Epistemic Uncertainty)과 매우 높은 상관관계를 갖습니다. 모델이 겉으로는 확신하더라도 내부적으로 의견이 엇갈리는 고확신 오탐(Overconfidence)을 방어합니다.

### 2.3. 분석 난이도 (Analysis Difficulty)
* **지표**: PEFormatWarnings 피처들의 합산 점수 (`difficulty_score >= 1.0`)
* **근거**: PE 파싱 과정에서 발생하는 경고(Warning)의 개수를 측정합니다. 구조적 결함이 있거나 난독화, 패킹 등이 적용된 악의적인 파일들을 구조적 관점에서 즉각 식별합니다.

### 2.4. 확률 그레이존 (Uncertain Probability)
* **지표**: Isotonic Regression으로 보정된 LightGBM 예측 확률 (`0.60 < p_calib < 0.983645`)
* **근거**: 확률값이 명확한 자동 정상(0.60 이하)이나 자동 악성(0.983645 이상)의 임계값에 도달하지 못한 모호한 영역(그레이존)의 샘플들입니다. 기계학습 모델 스스로가 최종 판정을 내리기 어려워하는 불확실성 영역을 촘촘하게 방어합니다.

### 2.5. 라우팅 판정 로직 (Waterfall OR 조건)
시스템은 위 4가지 위험 신호를 병렬적으로 모두 계산해 둔 뒤, 라우터에서 순차적(`if-elif`)으로 하나씩 검사합니다.
결과적으로 **4개의 위험 신호 중 단 1개라도 기준치를 넘는다면 즉시 심층 분석(HIGH_RISK_UNCERTAIN) 큐로 라우팅**되는 매우 보수적이고 방어적인 체계로 작동합니다. 위 4개의 조건을 모두 무사히 통과한 파일들만 안전한 파일(자동 정상) 또는 명백한 악성 파일(자동 악성)로 최종 분류됩니다.

## 3. 테스트 스크립트 실행
테스트 스크립트는 메인 평가 파이프라인인 `src/jrr/evaluate_jrr.py` 내부에 통합되어 자동 실행됩니다.

```bash
# 가상환경 활성화 후 실행
python src/jrr/evaluate_jrr.py
```

### 3.1. 스크립트 주요 흐름
1. `jrr_ood_scores.npy`, `model_disagreement.npy`, `jrr_difficulty_scores.npy`, 보정된 확률값 및 라우터 최종 판정(`jrr_routes.npy`) 로드.
2. 각각의 임계값을 초과하는 위험 샘플 인덱스 추출.
3. 해당 인덱스의 파일들이 `HIGH_RISK_UNCERTAIN`으로 올바르게 라우팅되었는지 검증.
4. 결과 통계(OOD 방어율, Kill Test 오탐률 등) 출력 및 MLflow 지표 등록.

## 4. JRR Threshold 튜닝 결과 (Calibration Set 기반)
Data Leakage를 완벽히 배제하기 위해, 모델의 임계값(Threshold)을 **오직 Calibration 데이터셋(48만 건)**만을 대상으로 전면 재튜닝했습니다.
이 결과를 바탕으로 최종 보고서 및 평가 프로토콜을 업데이트하시면 됩니다.

### 4.1 Phase 1: `tau_difficulty` (분석 난이도) 최적화

> **고정 상수**: `tau_low = 0.60`, `tau_disagree = 0.30`, `tau_ood = 0.0`
> **목적**: 심층 분석 큐의 병목 현상 해소 및 분석 타율(Review Yield) 방어

| 임계값(tau_diff) | 심층분석 비율 | 심층분석 건수 | Review Yield (타율) | 정상 중 악성 누출 건수(미탐) |
|:---|:---|:---|:---|:---|
| **1.0** | 55.81% | 267,894건 | 69.85% | 4,138건 |
| **2.0** | 49.03% | 235,344건 | 73.66% | 4,492건 |
| **3.0** | 25.94% | 124,524건 | 65.44% | 4,818건 |
| **4.0** | 22.78% | 109,366건 | 61.80% | 4,860건 |
| 👉 **5.0** | **14.15%** | **67,910건** | **71.83%** | **4,954건** |
| **6.0** | 9.08% | 43,596건 | 74.79% | 4,970건 |
| **7.0** | 7.89% | 37,850건 | 73.98% | 5,006건 |
| **10.0** | 6.00% | 28,802건 | 68.35% | 5,030건 |

💡 **5.0 선정 근거 (Calibration 기준):**
* **트래픽 급감 지점 (Elbow Point):** 임계값이 4.0에서 5.0으로 넘어갈 때, 심층 분석 큐로 유입되는 트래픽이 22.7%에서 **14.1%**로 극적으로 감소하며 병목이 해소됩니다.
* **타율(Yield) 반등:** 4.0에서 61.8%까지 떨어졌던 타율이 5.0에서 **71.83%**로 수직 반등합니다. 6.0 이상으로 올리면 타율이 소폭 상승하지만(74%), 정상 큐로 누출되는 악성 샘플이 증가하기 시작하므로 방어력과 가성비의 최적 타협점은 **5.0**입니다.

### 4.2 Phase 2: `tau_low` (확률 그레이존 하한선) 최적화

> **고정 상수**: `tau_difficulty = 5.0`, `tau_disagree = 0.30`, `tau_ood = 0.0`
> **목적**: 확률 그레이존의 최적 하한선 도출 (수용 가능한 악성 누출 내에서 타율 극대화)

| 임계값(tau_low) | 심층분석 비율 | 심층분석 건수 | Review Yield (타율) | 정상 중 악성 누출 건수(미탐) |
|:---|:---|:---|:---|:---|
| **0.50** | 14.52% | 69,690건 | 71.53% | 3,888건 |
| 👉 **0.60** | **14.15%** | **67,910건** | **71.83%** | **4,954건** |
| **0.70** | 14.07% | 67,558건 | 71.88% | 5,174건 |

| **0.98** | 11.83% | 56,808건 | 69.28% | 14,378건 |

💡 **0.60 선정 근거 (Calibration 기준):**
* 하한선을 0.50에서 0.60으로 상향할 때 타율(Yield)이 71.83%로 최고조에 달하며 안정화됩니다.
* 0.60을 넘어서 0.70, 0.80으로 하한선을 계속 올리면 타율은 거의 오르지 않는 반면, **자동 정상(Auto Benign)으로 우회하여 누출되는 악성 샘플 수가 급증(4,954건 ➡️ 7,248건)**합니다.
* 따라서 타율을 최고점으로 유지하면서도 미탐(Leakage)의 급격한 증가를 방어할 수 있는 최적의 마지노선이 **0.60**입니다.

## 5. 시뮬레이션 통합 결과 요약 (최근 48만 건 평가 기준)

### 🛡️ 1. OOD (Out-of-Distribution) 이상 탐지 방어 결과
* **식별 결과**: 랜덤 유니폼 샘플링으로 재학습된 `IsolationForest` 모델이 48만 건 중 **3,384개**의 낯선 패턴(OOD Score < 0.0)을 식별했습니다.
* **치명적 오탐(Kill Test FPR) 완벽 방어**: 이 3,384개의 OOD 파일 중 실제로는 정상 파일임에도 불구하고 모델이 악성이라고 확신(확률 0.98 이상)한 파일이 **2건** 존재했습니다. 만약 OOD 방어 로직이 없었다면 이 2건은 고스란히 오탐(FP)으로 이어져 치명적인 시스템 장애를 유발했을 것입니다. 하지만 OOD 점수 로직이 이를 완벽하게 가로채어 모두 `HIGH_RISK_UNCERTAIN` 큐로 격리시킴으로써 **100%의 방어 성공률(Kill Test FPR 0%)** 을 달성했습니다.

### 🛡️ 2. 모델 불일치도 방어 결과
* **방어율 100% 달성**: 두 모델 간의 불일치도가 0.3 이상으로 벌어진 약 **11,728개**의 불확실한 샘플들 또한 100% 확률로 심층 분석에 보내져, 고확신 오판을 효과적으로 방어했습니다.

### 🛡️ 3. 분석 난이도 (PE 파싱 결함) 방어 결과
* **식별 결과**: PEFormatWarnings 기반의 합산 점수가 임계값(5.0) 이상인 파일은 총 **46,214개 (9.63%)** 로 확인되었습니다.
* **Review Yield (심층 분석 타율) 76.68%**: 임계값을 1.0에서 5.0으로 튜닝함에 따라, 정상 파일이 심층 분석으로 불필요하게 격리되는 비율이 35%에서 3.78%로 극적으로 감소했습니다. 그 결과, 심층 분석 큐로 들어온 전체 파일 77,784개 중 무려 **76% 이상이 실제 악성코드**로 꽉 찬 고순도 방어망이 구축되었습니다.
* *(참고: 이를 통해 58%에 달하던 심층 분석 병목 현상을 16%까지 낮추어 라우터의 효율성을 대폭 끌어올렸습니다.)*

### 🛡️ 4. 확률 그레이존 (Uncertain Probability) 방어 결과
* **라우팅 결과**: 앞선 3가지 치명적 위험 신호(OOD, Disagreement, Difficulty)가 없는 비교적 평범한 파일들 중에서도, 예측 확률이 그레이존(0.60 ~ 0.9836)에 해당하는 경우 100% 안전하게 심층 분석으로 분기되었습니다.

## 7. 심층 분석: 위험 신호 오버랩(Overlap) 현황

4가지 위험 신호가 서로 얼마나 독립적으로 동작하는지 확인하기 위해 48만 건 전체 데이터의 식별 현황을 분석했습니다.
* 어떠한 조건에도 걸리지 않음 (자동 정상/악성 직행): 402,216건 (83.80%)
* **딱 1개 조건만 만족**: 69,924건 (14.57%)
* **2개 조건 동시 만족**: 7,658건 (1.60%)
* **3개 조건 동시 만족**: 202건 (0.04%)
* **4개 조건 모두 만족**: 0건 (0.00%)

👉 **분석 결론**: 조건이 2개 이상 겹치는 샘플이 전체의 1.64%에 불과합니다. 이는 4가지의 서로 다른 위험 신호들이 각자의 위치에서 '서로 다른 유형'의 결함들을 독립적으로 아주 훌륭하게 방어하고 있음을 증명합니다.
