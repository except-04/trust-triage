# TRUST-triage: JRR 평가 및 임계값 최적화 파이프라인 가이드

본 문서는 JRR(Joint Risk Router) 시스템이 파일을 3갈래로 분배하기 위한 **최적의 기준선(Threshold)을 찾고, 최종적인 라우팅 성능을 검증하기 위해 구축된 3개의 핵심 파이프라인 모듈**에 대한 설명서입니다. 

의존성 충돌(순환 참조)을 방지하고 코드의 재사용성을 높이기 위해 공용 도구함과 실행 스크립트를 완벽하게 분리하여 설계했습니다.

---

## 1. jrr_eval_utils.py (공용 평가 도구함)
평가 지표를 계산하는 수학적 로직들만 모아둔 **'순수 함수 모음집'**입니다. 번호표가 없는 독립적인 모듈이므로, 파이프라인의 어느 단계에서든 자유롭게 `import` 하여 사용할 수 있습니다.

*   **주요 기능:**
    *   `calculate_ece()`: 모델의 예측 확률과 실제 정답률 사이의 신뢰도 오차(ECE)를 계산합니다.
    *   `calculate_review_yield()`: 분석가의 일일 검토 예산(T) 한도 내에서, 심층 분석 큐로 이관된 파일들이 실제 악성코드를 얼마나 잘 방어해 냈는지 가성비(%)를 계산합니다.
*   **활용:** 09번 최적화 모듈과 11번 평가 모듈 모두 이 파일에서 함수를 불러와 사용합니다.

## 2. 09_optimize_threshold.py (임계값 최적화 시뮬레이터)
JRR 메인 라우터(10번)가 조립되기 **직전**에 실행되어, 분석가의 예산을 초과하지 않으면서 최적의 가성비를 내는 **'심층 분석 하한선(Lower Bound)'**을 찾아내는 시뮬레이터입니다.

*   **주요 로직:**
    *   07번 모듈에서 산출된 '절대 차단선(상한선)'을 로드하여 기준으로 삼습니다.
    *   하한선 점수를 0.1부터 상한선 직전까지 0.05 단위로 움직여가며 `_jrr_eval_core.py`의 수율 계산 함수를 반복 호출합니다.
    *   **산출물:** 가성비(Review Yield)가 가장 극대화되는 최적의 점수를 터미널에 출력합니다.
*   **후속 작업:** 여기서 도출된 점수를 `10_jrr_router.py` 내부의 분기 조건(If-Else)에 업데이트해야 메인 라우터가 최종 완성됩니다.

## 3. 11_evaluate_jrr.py (최종 성능 평가 및 Kill Test)
10번 라우터(가영님 담당)가 완성된 후, 라우터를 통과하여 분배된 최종 결과물(큐 할당 내역)의 성능을 평가하고 극한의 스트레스 테스트를 진행하는 최종 검증 스크립트입니다.

*   **주요 로직:**
    *   **지표 측정:** 실제 데이터와 라우터의 예측값을 비교하여 최종 ECE 점수와 Review Yield를 확정합니다.
    *   **Kill Test (스트레스 테스트):** 신종 악성코드(OOD) 및 꼬여있는 정상 파일 등 극한의 데이터셋을 주입하여, 프로젝트의 최후 방어선인 **정상 오탐률(FPR) 0.1%**가 뚫리지 않는지 최종 점검합니다.
    *   **결과 기록:** 도출된 최종 성능 지표들을 MLflow 서버(`JRR_Evaluation_and_KillTest` 실험 공간)에 자동 박제하여 팀원 누구나 열람할 수 있도록 지원합니다.

## 🔄 데이터 흐름 및 실행 순서 (Workflow)
원활한 파이프라인 구동을 위해 반드시 아래의 순서대로 스크립트를 실행 및 연동해 주시기 바랍니다.

1.  **[실행] `09_optimize_threshold.py`**: 시뮬레이터를 돌려 최적의 하한선 점수 도출
2.  **[수동] `10_jrr_router.py` 업데이트**: 09번에서 찾은 하한선 점수를 10번 메인 라우터 조건문에 입력하여 엔진 완성
3.  **[실행] `10_jrr_router.py`**: 완성된 엔진에 평가용 데이터셋을 주입하여 최종 예측물(`routes.npy` 등) 생성
4.  **[실행] `11_evaluate_jrr.py`**: 생성된 결과물을 바탕으로 최종 성적표 발급 및 Kill Test 수행
