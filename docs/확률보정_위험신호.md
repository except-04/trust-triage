## 1. 07번: 확률 보정기 (Calibration) 파이프라인
`src/jrr/07_train_calibrator.py`

### 목적
AI(Baseline 모델)가 내뱉는 과장된 원시 예측 확률을 현실적인 신뢰도로 **영점 조절**합니다.
수행계획서의 강력한 방어선인 **'정상 오탐률(FPR) 0.1% 이하'**를 달성하기 위한 최적의 임계값(Threshold)을 계산하고 확정합니다.

### 핵심 알고리즘
* **Isotonic Regression (등방성 회귀):** 예측 확률의 순서를 유지하면서 실제 정답 라벨에 맞게 계단식으로 확률을 보정합니다.

### 📥 필요 데이터 (Input)
아래 파일들이 반드시 프로젝트 최상위 `data/` 폴더 내에 있어야 합니다.
* `data/y_calib.npy` : 40~45주차 Calibration용 실제 정답지
* `data/y_pred_proba.npy` : Baseline 모델을 통해 추출한 원시 예측 확률값

### 📤 산출물 (Output)
* **로컬:** `jrr_calibrator.pkl` (학습된 보정기 및 최적 임계값 내장)
* **MLflow:** `JRR_Calibration` 실험 공간에 메트릭(최적 임계값, 탐지율 등) 및 모델 박제

## 2. 08번: 다중 위험 신호 (Risk Signals) 산출 파이프라인
`src/jrr/08_train_risk_signals.py`

### 🎯 목적
단순한 악성/정상 확률 점수만으로는 판단하기 어려운 **'애매한 그레이존(보류 구간)'** 파일들을 색출하기 위한 **3대 위험 신호** 부품을 생성합니다.

### ⚙️ 핵심 로직
1. **OOD (Out-of-Distribution) Score:** 과거 학습 데이터와 패턴이 얼마나 다른지(신종 의심도)를 `Isolation Forest` 모델을 통해 학습합니다.
2. **Analysis Difficulty (분석 난이도):** 스키마의 `PEFormatWarnings`(원본 2480~2568) 피처 그룹이 최종 Top 500 배열 안에서 몇 번째 인덱스로 이사했는지 **동적으로 추적하고 매핑**합니다.
3. **Model Disagreement (모델 간 불일치도):** 이 지표는 학습이 아닌 추론 단계에서 앙상블 분산으로 계산되므로 본 스크립트에서는 설계를 패스. router 단계 아마 09가 될듯

### 📥 필요 데이터 (Input)
* `data/X_tr.npy` : OOD 기준점 학습을 위한 원본 학습 데이터 (메모리 절약을 위해 mmap 로드 및 샘플링 적용)
* `data/top_feature_indices_500.npy` : 특징 추출 모듈(상욱님 파트)에서 산출된 상위 500개 피처 인덱스 정보

### 📤 산출물 (Output)
* **로컬:** `jrr_risk_signals.pkl` (Isolation Forest 모델 및 동적 난이도 인덱스 맵핑 정보 내장)
* **MLflow:** `08_ood_isolation_forest` 모델 서버 기록
