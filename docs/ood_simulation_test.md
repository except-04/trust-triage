# OOD Simulation Test Guide

## 1. 개요
본 문서는 TRUST-Triage 파이프라인에서 OOD(Out-of-Distribution) 샘플들에 대한 시스템 반응을 테스트하는 **OOD 시뮬레이션 방법론**을 설명합니다.

OOD 데이터는 학습 데이터의 분포를 벗어난 "낯선 데이터"(신종 악성코드 등)로, 기계학습 모델이 지나치게 확신하여(Overconfidence) 오탐을 발생시킬 수 있는 주요 위험 요인입니다. 우리 시스템은 이러한 위험 샘플을 `HIGH_RISK_UNCERTAIN` 큐로 라우팅하여 심층 분석(CAPA, Speakeasy 등)을 받도록 설계되어 있습니다.

## 2. 테스트 방법론
새로운 외부 OOD 데이터셋을 수집하는 대신, 기존 평가 데이터셋(`X_eval`) 내에서 통계적으로 가장 이질적인 샘플을 추출해 가상의 OOD 테스트셋으로 활용합니다.

### 2.1. OOD 점수 산출
* **지표**: 두 개의 서로 다른 모델(XGBoost, LightGBM) 간의 예측 확률 불일치도 (Model Disagreement)
* **근거**: 앙상블 모델 간의 의견 불일치도(`|p_xgb - p_lgb|`)는 인식론적 불확실성(Epistemic Uncertainty)과 매우 높은 상관관계를 가지며, OOD 데이터를 식별하는 강력한 프록시 지표로 사용될 수 있습니다.

### 2.2. 샘플 추출
* 평가 데이터에 대한 `model_disagreement.npy` 값의 히스토그램 분포를 분석한 결과, 점수가 `0.3` 이상인 구간부터 뚜렷한 Long Tail(꼬리) 형태가 나타남을 확인했습니다.
* 이에 따라 통계적으로 이질성이 급격히 커지는 **Threshold 0.3 이상**의 샘플들을 **OOD 데이터셋**으로 간주합니다.

## 3. 테스트 스크립트 실행
테스트 스크립트는 별도의 파일 없이, 메인 평가 파이프라인인 `src/jrr/evaluate_jrr.py` 내부에 `evaluate_ood_routing` 함수로 통합되어 자동 실행됩니다.

```bash
# 가상환경 활성화 후 실행
python src/jrr/evaluate_jrr.py
```

### 3.1. 스크립트 주요 흐름
1. `data/model_disagreement.npy`와 `data/jrr_routes.npy` 로드.
2. 불일치도 점수가 0.3 이상(Threshold >= 0.3)인 인덱스 추출.
3. `jrr_routes.npy`에 기록된 라우터 최종 판정 결과 중 OOD 인덱스에 해당하는 결과 확인.
4. 결과 통계 (자동 정상, 자동 악성, 심층 분석) 출력 및 MLflow 지표(OOD_Defense_Rate) 등록.

## 4. 시뮬레이션 결과 요약
* **Threshold 0.3 기준 (약 2.45%, 11,728개)**: 추출된 11,728개의 OOD 샘플이 모두 오탐 없이 `HIGH_RISK_UNCERTAIN`으로 라우팅되어 **100% 방어에 성공**했습니다.
* **(참고) Top 1% 극단값 기준 (4,800개)**: 시스템 초기 검증 단계에서 전체 48만 개 중 가장 불일치도가 심한 최상위 1% 데이터를 대상으로 테스트했을 때도, 단 1건의 오탐 없이 **100% 방어를 달성**한 바 있습니다. 
* 두 가지 방식(통계적 꼬리 분포 및 최상위 극단값) 모두에서 완벽한 방어율을 기록하였으므로, 현재 라우터 엔진에 하드코딩된 불일치도 임계값(`tau_disagree=0.3`)이 모델 오판을 방지하는 데 매우 효과적이고 안정적임을 입증합니다.
